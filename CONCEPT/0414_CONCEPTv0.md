# Kurumi（仮）— そっと、近づく。

> すれ違いから、ことばが生まれる。大学生のためのゆるやかな出会い。

本ドキュメントは技術仕様ではなく、**プロダクト思想の認識合わせ**を目的とする。
「なぜ作るのか」「何を作らないのか」をチームで共有するための北極星。

> ⚠️ **プロダクト名について**：本書中の「Kurumi」は仮称です。正式名称は未確定で、
> ロゴ・ドメイン・ストア表記などの最終決定前に再検討します。機能や思想が固まった段階で、

## 1. ユーザーの「夜も眠れない課題」

### 誰の、どんな痛み

**大学生（特に1〜3年）**。講義・サークル・バイトで毎日同じ空間に誰かがいるのに、
「話しかけるほどじゃない。でも、気になる。」という**中間の距離**が行き場を失っている。

- **SNS疲れ**：Instagram / X は "完成された自己" を見せ合う場で、素の興味はむしろ出しにくい。
- **マッチングアプリ疲れ**：恋愛/性的文脈が前提になり、「ただ趣味が近い人と話したい」は居場所がない。
- **サークル・授業のハードル**：所属の意思表明が必要で、気軽な「のぞき見」が許されない。
- **すれ違いの消失**：同じカフェで毎週見かける人、同じ講義に出てる人 — 誰なのか一生わからない。

### なぜ夜も眠れないか

孤独は静かに積もる。「今日も誰とも深い話をしなかった」という感覚は、
自己責任論（＝「話しかけなかった自分が悪い」）に回収されやすく、**次の日にまた同じ一日が来る**。
既存SNSは「もっと発信しろ」「もっと繋がれ」と圧をかけるが、本当に欲しいのは**静かな足がかり**だ。

## 2. インパクトのあるアプローチ

### 一行で言うと

**「プロフィールは、最初からは見えない。近くにいて、共通点があったぶんだけ、ひらく。」**

### 既存解との違い

| | 既存SNS / マッチング | Kurumi |
|---|---|---|
| 初期状態 | 全開示（自己PR） | **マスク**（断片だけ） |
| つながる契機 | フォロー/いいね/スワイプ | **物理的な近接 × 興味の重なり** |
| 言葉の温度 | 公開・拡散前提 | 1対1の、静かな発見 |
| 目的 | 承認 / マッチング | **気配の共有** |

### なぜこれがインパクトあるのか

- **"見られない安心" から始まる**。マスクが初期状態なので、自己PRのプレッシャーがない。
- **偶然を設計する**。近接 + タグ重なりという "偶然っぽい必然" が、能動的アクションのハードルを下げる。
- **ひらくのは自分のペース**。断片ごとに `public / masked / conditional` を選べ、
  「共通点がある人にだけ見せる」という新しい距離感を実装する。

## 3. 推しポイント

「一言で自慢できる、他にないところ」。デモ・ピッチ・ストア掲載文で使う **3つの刺さり** ↓

### 🪶 推し① — 名刺が、虫食いのまま渡される
既存の出会いアプリは「先に見せる／全部見せる」が前提。Kurumi は**最初は"ほぼ何も見えない名刺"**を渡す。
情報の出し惜しみが、逆に好奇心を生む。プロフィールを埋めるゲームではなく、**相手と一緒にめくるゲーム**。

### 🐛 推し② — 芋虫が、共通点をほどく
共通点が見つかった瞬間、名刺の上を**小さな芋虫が這って虫食いをほどく**。
マッチング＝スワイプではなく、マッチング＝**見守る小さなアニメーション**。機能より先に、画面が可愛い。

### 🌫 推し③ — "すれ違い"を、プロダクトが肯定する
SNSは「今すぐDMを送れ」と急かし、マッチングアプリは「会う約束をしろ」と急かす。
Kurumi は **"まだ、かくれている"という状態** を正式なステータスとして持つ。
「話しかけないまま、同じ場所に居ること」を失敗ではなく体験として扱う、初めてのプロダクト。

## 4. 価値（勝ち筋）

### 4.1 ユーザーにとっての価値

- **低負荷な自己開示** — プロフィールを完璧に書かなくていい。虫食いのままでいい。
- **拒絶の不在** — スワイプもDMも無いので「既読無視された」「いいね来ない」が構造的に発生しない。
- **偶然の物語化** — 何気ないすれ違いが「名刺がほどけた日」として記憶に残る。

### 4.2 なぜ今のマーケットで勝てるか（勝ち筋）

| 他社が取れない理由 | Kurumi が取れる理由 |
|---|---|
| マッチングアプリは売上構造上、スワイプ/課金から逃げられない | 非マッチング。**恋愛文脈を持ち込まない**ので学生が素直に使える |
| SNS大手は "承認の量" で最適化されたアルゴリズムに縛られる | アルゴリズム最小。**偶然**に全振りできる |
| 既存の学内アプリ（Yenta学生版等）は "繋がる" が前提 | **繋がらない状態** を正式に扱う |

### 4.3 ビジネス上の勝ち筋（長期）

- **大学単位の導入**：学食・生協・学内広告のチャネルと親和性が高い（静かなトーン）。
- **B2B2C余地**：カフェ・シェアオフィスなど「滞在×偶然」の場所と組める。
- **データは蓄積しない構造**を逆に資産化：プライバシー重視ブランドとしての信頼。
- **キャラクター（芋虫→蝶）のIP化**：スタンプ・グッズ等、情緒的なブランド展開が可能。

### 4.4 勝ち筋の前提（崩れると詰む条件）

- 大学生の「SNS疲れ」が今後も続く（継続すると予想）。
- 近接検知がブラウザ/PWAで十分に体験可能（BLE/位置で代替）。
- "ひらく前の状態" が我慢できるだけの演出クオリティを担保できる（← ここが最大リスク）。

## 5. ここがコア機能

### 5.1 断片カード = "虫食いの名刺"

Kurumi の基本単位は「**虫食いの名刺**（masked card）」。
名刺は本来、**会った瞬間に全情報が渡される**メディアだが、Kurumi はその前提を裏返す。

- 名刺には **カテゴリ・タイトル・中身・タグ** があるが、最初は**ほとんどが虫食い（●●●）で隠れている**。
- 相手と「共通点」が見つかるたびに、名刺の**穴が少しずつ埋まっていく**。
- 全部埋まると、初めて "完全な一枚の名刺" として相手のConnectionsに残る。

> 従来の名刺：`［所属・肩書・連絡先・SNS］` を一度に渡す
> Kurumi の名刺：`［● ● ● ● ●］` → `［● 読書 ● ● ●］` → `［写真 読書 映画 ● ●］` → 完成

この「**一枚の名刺が、出会いの回数だけ埋まっていく**」という感覚が Kurumi の体験の土台。

### 5.2 Reveal Sequence（虫食いが埋まる瞬間）

Kurumi の演出の中心は、**すれ違い→共通点検知→虫食いが埋まる**アニメーション体験。

1. 街やキャンパスで、相手と近接（擬似BLE / 位置判定）。
2. 双方のタグが重なっていれば、マッチ候補に浮上。
3. `/match/[id]` で **Reveal Sequence** が走る：
   - 霧が晴れるように、マスクされていた断片カードが1枚ずつ開く。
   - 開くのは **共通点に紐づくカード** だけ。他は霧の中。
   - 最後に「共通点 N個が見つかりました」と、静かに着地。

### 5.3 演出アイデア：「芋虫が、虫食いをほどく」

虫食いの名刺を、**芋虫（キャラクター）が這って開示していく**という演出案。

- 名刺の伏字（●●●）の上を、小さな芋虫がゆっくり這う。
- 芋虫が通った跡が**すりガラスから明瞭な文字に変わる**（マスクの逆アニメーション）。
- 共通点が多いほど芋虫は元気に動き、少ないと途中で眠ってしまう。
- 最後、すべての共通点を埋め終わった芋虫は**蝶になって飛んでいく**（= Connectionsへ登録）。

> なぜ芋虫か：「虫食い」という言葉の比喩を素直に拾うキャラクター。
> 威圧感がなく、ゆっくり・可愛い・攻撃的でない。Kurumi の静かな世界観に馴染む。
> 別案：霧が指先で拭われていく／砂が風で払われる／本のページが捲れる など。要検討。

「**機能ではなく、情緒**」が差別化要因。UIの"動き"そのものがプロダクトの価値。

## 6. デザイン

本節は**UIデザインのたたき**。ビジュアル言語・画面構成・虫食い演出の具体案をチームで揃えるための初期案。
実装確定ではなく、**議論のスタート地点**として提示する。

### 6.1 ビジュアル言語（トーン & ムード）

| 要素 | 方向性 |
|---|---|
| **全体印象** | 和紙・朝靄・すりガラス。**白すぎない白**（#FAF7F2 付近）と、霧のような半透明レイヤー |
| **配色** | ベース: warm-sand / paper / fog（すべて低彩度）<br>アクセント: ember-gold（#C9A24B 付近）— 光が差す瞬間にだけ使う |
| **タイポ** | 和文は明朝（Shippori Mincho）で静けさを、欧文は Inter でニュートラルに |
| **余白** | 情報密度を下げる。**何もない空間**こそが "気配" を伝える |
| **モーション** | easing `[0.2, 0.8, 0.2, 1]`（ease-out強め）。速い動きは禁止、**常にゆっくり** |

### 6.2 画面構成のたたき

```
┌─────────────────────────┐
│        PresenceOrb       │  ← 自分の気配。ゆっくり脈打つ
│         "あなた"          │
│                         │
│  ─── 近くに、3人 ───      │
│   ◌    ◌    ◌           │  ← 他者Orb（名前はまだ無い）
│                         │
│  ─── 今日の断片 ───       │
│  ┌──────┐ ┌──────┐      │
│  │ ●●●● │ │ 写真 │      │  ← 虫食いカード / 公開カード
│  │ ●●●● │ │ film │      │
│  └──────┘ └──────┘      │
│                         │
│ [home][探] [つながり][設]│  ← BottomNav
└─────────────────────────┘
```

### 6.3 虫食いカード（MaskedCard）のデザイン案

```
─────────────────────────
  HOBBY                     ← カテゴリ（常時表示）
  ●●●●●                    ← タイトル伏字（8-12文字）
  ────────
  ●●●●●●●●●●●●            ← 本文伏字（すりガラス風）
  ●●●●●●●●●
  ●●●●●●●●●●
  ────────
  # ●●●  # ●●●  # ●●●     ← タグも虫食い
─────────────────────────
```

**虫食いの表現案**：
- A. **●● ドット伏字**（現状の素直な実装） — 読めないが"文字があること"は伝わる
- B. **すりガラス blur + 下に影テキスト** — 実装軽め、情緒重め
- C. **墨を落とした紙ふう** — 和の世界観と強く整合。SVGで表現
- D. **文字が渦を巻いて見えない** — 実験的。好奇心を最大化

推奨は **B + C のハイブリッド**：和紙テクスチャの上に、墨をにじませた虫食い。

### 6.4 芋虫アニメーション（キャラクター案）

```
 before:  ●●●●●●●●●●●●●●●
                 🐛→             ← 芋虫が左→右に這う
 during:  写真●●●●●●●●●●●●
                      🐛→
 after:   写真が、好きです。
                        🦋       ← 完了で蝶に
```

**キャラクター設計指針**：
- 幾何学形（楕円×3セグメント）。丸くて柔らかい。
- 色はember-goldに近いくすんだ琥珀。目は小さな点二つ。表情は描かない。
- 速度は **60-80px/sec** 程度（急がない）。
- 蝶への変化は **最後の1枚が完成した瞬間のみ**。レア演出。

別案（要議論）：
- 霧が指先で拭われる（人の手の比喩）
- 和紙が水を含んで透けていく
- 和本のページを風がめくる

### 6.5 PresenceOrb（気配）のデザイン

- avatarSeed から決定論的に生成する **ぼんやりした光の玉**。
- `intensity` プロパティで距離感を表現（遠い＝薄い、近い＝濃い）。
- **顔写真は絶対に使わない**。Kurumi の思想上、人物の可視化は禁じ手。

### 6.6 画面遷移の情緒

- 画面遷移は全て **fade + 10px 程度の上下スライド**。左右スワイプ系は使わない。
- Reveal Sequence中は **ページ下部のBottomNavを消す**。没入の邪魔をしない。
- "すべてを忘れる"（reset）を押した直後は、**1秒間の白いフェード**を挟んで世界がリセットされた感を演出。

## 7. 外せない機能たち（MVP Scope）

| # | 機能 | なぜMVPに必要か |
|---|---|---|
| 1 | **オンボーディング（S1）** | 断片カードを自分の手で作るプロセスが、プロダクトへの愛着を決める |
| 2 | **プレゼンス表示（S2 / Home）** | 「今、近くに誰かいる」気配を可視化。PresenceOrb で人格を記号化 |
| 3 | **近接検知 → Reveal（S3→S4）** | コア体験。ここが弱いとプロダクトの意味が消える |
| 4 | **Person ページ（S5）** | ひらいた断片／まだかくれている断片を、相手ごとに閲覧 |
| 5 | **Connections（S6）** | 「ことばを交わした／ひらいた／まだかくれている」の3段階で過去を振り返る |
| 6 | **Settings：可視性切替（S7）** | `public / masked / conditional` を断片ごとに切替。"距離感の設計" がユーザー主導 |
| 7 | **Reset（デモ用）** | "すべてを忘れる" を明示することで、Kurumi の思想（軽さ・可逆性）を伝える |

## 8. あえて「やらない」こと

Kurumi を Kurumi たらしめるため、MVPでは以下を**意図的に実装しない**。

- ❌ **チャット機能** — 「ことばを交わす」は演出として扱い、実チャットは外部（LINE等）に委ねる。
  Kurumi の中で会話を完結させると、「もう一つのDMアプリ」に堕ちる。
- ❌ **恋愛マッチング / スワイプ / いいね** — マッチングアプリ的文脈を完全に排除。
- ❌ **リアルタイム位置情報の厳密同期** — プライバシーと思想の両面で NG。"気配" で十分。
- ❌ **おすすめAI / パーソナライズレコメンド** — 偶然性が死ぬ。アルゴリズムで最適化しない。
- ❌ **プロフィール完成度ゲージ / 埋めるほど有利な仕組み** — "ひらくのは自分のペース" に反する。
- ❌ **ネイティブアプリ** — MVP は Web (PWA)。スピードと可搬性を優先。
- ❌ **通知の最大化** — 鳴らしすぎない。Kurumi は静かなプロダクトであるべき。

## 9. プロダクトの詳細な仕様

### 9.1 ユーザーストーリー

- **S1 オンボーディング**：表示名・学部・学年を入力し、5〜7枚の断片カードを作る。
  カテゴリは `hobby / topic / trouble / value / current`。各カードにタグを付与。
- **S2 Home**：自分の断片一覧と、近接中の他ユーザーの PresenceOrb を表示。
- **S3 近接**：同じ場所に居続けると、相手が候補としてリストアップ。
- **S4 Reveal**：共通点があった場合、Reveal Sequence が走り、一致したカードだけが開く。
- **S5 Person**：特定の相手のひらいた断片／かくれた断片を閲覧。開示率を %で可視化。
- **S6 Connections**：過去の出会いを「ことばを交わした／ひらいた／まだかくれている」で分類。
- **S7 Settings**：断片ごとに可視性を `public / masked / conditional` で循環切替。

### 9.2 カード可視性ルール

| visibility | 初期状態 | ひらく条件 |
|---|---|---|
| `public` | 最初から見える | 常時公開 |
| `masked` | 霧の中 | マッチ成立で開示 |
| `conditional` | 霧の中 | **共通点タグがあるときだけ**開示 |

`conditional` が Kurumi の肝。「全員に見せる／誰にも見せない」の二択を壊す、**第三の距離感**。

### 9.3 エッジケース

- 共通点ゼロのすれ違い → Reveal Sequence は走らず、`masked` のまま Connections に残る。
- 同じ相手と複数回近接 → マッチは1つに統合、`metAt` を更新。
- カード可視性を途中で変更 → 次回の近接以降に反映。過去のReveal結果は遡及して消さない。

## 10. 成功の定義

### 北極星メトリクス

**「ひらいた断片の累計数」** — ユーザーが Kurumi の中で "距離を縮めた" 量の総和。
DAU でも MAU でもなく、**一人あたりがどれだけ "ひらいたか"** を追う。

### サブ指標

| 指標 | なぜ見るか | MVP目標 |
|---|---|---|
| 近接 → Reveal 完走率 | コア演出が機能しているか | 80% 以上 |
| Reveal → Connections 遷移率 | 出会いが記憶に残ったか | 60% 以上 |
| 可視性の「conditional」設定率 | 第三の距離感が使われているか | カードの30%以上 |
| 週次リテンション（W1/W2） | 静かに戻ってくるプロダクトか | W1: 40% / W2: 25% |
| "すべてを忘れる" 実行率 | 軽さ・可逆性が負荷になっていないか | 5%未満（高すぎると定着失敗） |

### 定性の成功条件

- ユーザーが「**昨日、いつものカフェで誰かとひらいた**」と日常会話で語れる。
- 「Kurumi って何のアプリ？」に対して、誰もが「**マッチングじゃなくて、気配のアプリ**」と返せる。
- SNSでの流入/拡散ではなく、**対面での紹介**が最大の獲得経路になる。
